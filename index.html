Ontology matching with knowledge retrieval and large language models

KROMA matches concepts across two ontologies. These pages are the Python API: what you call, and what it returns.

$ git clone https://github.com/lamng3/kroma.git && cd kroma
$ ./setup.sh && source .venv/bin/activate
$ kroma run --help

What KROMA asks the model

real prompts, recorded answers

    

    
Mouse–Human anatomy pairs. The prompt is built by KROMA's own loader and build_task_prompt from the two ontologies. The answer is what the routed run in the Agentic Ontologist recorded for the pair, and the tier that settled it: an evidence-only answer never reached a model. The page asks no model.

  







A run loads an alignment, retrieves local context for each concept, asks a language model whether the pair matches, and refines the joined graph. The command line is the usual entry. The same steps are available as functions.


The pieces



CLIkroma run and the flags that select a config, a model, and a mode.
Matching runMatchingRun prepares the task, scores pairs, and writes metrics.
LoadersCSV alignments and an OWL class hierarchy.
QueryParents, children, synonyms, and labels from a named source.
ModelsOpenAI and Together chat models, and embedding backends.
RetrievalCosine search over concatenated text and Node2Vec vectors.
RefinementOnline updates while scoring, and a final offline collapse.
MetricsPrecision, recall, and F1 for a binary alignment.
